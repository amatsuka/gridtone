# Общие правила для агента планирования этапа Gridtone

Ты работаешь автономно в репозитории /Users/macbook/work/gridtone (Electron-приложение Gridtone). Пользователь ушёл и оставил компьютер включённым: задавать вопросы некому, AskUserQuestion не используй. Все решения принимай сам. Бери разумные дефолты, согласованные со спекой и прежними ADR.

Задача — только план, без реализации. Пользователь в такой ситуации открывает новую сессию, просит «составь план этапа N» и коммитит план. Сделай то же самое.

## Что прочитать
1. CLAUDE.md, его правила обязательны.
2. docs/progress.md:
   - границы этапов;
   - образцы планов: «## Этап 2. Редактор сетки — план», «## Этап 3. LUT — план», «## Этап 4. Анализ и гармония — план»;
   - записи последних подэтапов, особенно «Дальше» и «Отложено».
3. docs/spec.md: модуль или модули этого этапа, «Модель данных», «Экраны», «Риски и открытые вопросы».
4. docs/decisions/ и код в объёме, нужном для реалистичного плана: src/core, renderer, main, indexer, shared/ipc.ts, tests/e2e/helpers.ts.

## Как писать план
- Если у этапа ещё нет границ (раздела «Границы этапов …»), сначала допиши такой раздел по спеке. Пометь, что границы определены автономно.
- Раздел «## Этап N. <Название> — план» добавь в конец docs/progress.md, в том же формате, что прежние планы:
  - дата: сегодня, с пометкой, что план составлен автономно, без пользователя;
  - «Уже решено»;
  - «Общее для подэтапов»;
  - подэтапы (Nа, Nб, …). У каждого:
    - «Критерий»;
    - «Как проверяется»: конкретный e2e tests/e2e/stageNx.spec.ts на синтетических данных и модульные тесты;
    - «Шаги»;
  - «Отличия от спеки».
- Каждый подэтап должен помещаться в одну сессию агента примерно того же объёма, что 2а–4г. Он заканчивается проверяемым критерием, записью в журнал и коммитом.
- Открытые вопросы спеки, касающиеся этапа, реши сам дефолтом. Запиши их в «Уже решено» с короткой причиной. Нужные ADR укажи номерами (следующие свободные) в шагах подэтапов. Сами ADR пишутся при реализации.
- Новая зависимость — только если без неё никак. Укажи её в плане с обоснованием, ADR пишется при реализации. Нативные модули и модели машинного обучения — только если спека требует их на этом этапе и есть проверяемый критерий.
- Критерии должны проверяться автоматически (Playwright + Electron, Vitest), без глаз пользователя. То, что требует ручной проверки или вкуса пользователя, — в «Отложено» или в ручной чек-лист.
- Пиши кратко, по-русски, в стиле существующих записей.

## Закрытие
- Сделай один коммит в main. Ветку не создавай, push не делай. Сообщение: заголовок «План этапа N: <кратко> в K подэтапах», пустая строка, 2–4 строки сути по подэтапам, затем строка
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
- `git status` должен быть чистым.

## Финальный ответ оркестратору
Не длиннее 150 слов:
- хэш коммита;
- список подэтапов, по одной строке: идентификатор и название;
- ключевые дефолтные решения.

# 0003. Список ассетов в project.json

**Статус:** принято, 2026-10-06.

**Контекст.** Спека говорит, что оригиналы фото адресуются абсолютным путём и хэшем. Но в `Project` нет места, где бы они хранились: `Slot` ссылается на `assetId`, а путь и хэш есть только в `AssetFeatures`. Это строка SQLite-индекса библиотеки, а его на этапе 0 нет. Будь путь только в общей базе, проект перестал бы быть переносимой папкой.

**Решение.** `Project.assets: Record<string, AssetRef>`, ключ — `AssetRef.id`.

```ts
interface AssetRef {
  id: string;        // первые 16 hex-символов hash
  path: string;      // абсолютный путь к оригиналу
  hash: string;      // SHA-256 содержимого
  w: number; h: number; // с учётом EXIF-ориентации
  format: 'jpeg' | 'png' | 'webp' | 'tiff';
  icc: 'embedded' | 'assumed-srgb';
  importedAt: string;
}
```

**Последствия.**
- Проект открывается без индекса библиотеки. Индекс (`AssetFeatures`) остаётся отдельным кэшем признаков и связывается с проектом по `id` и `hash`.
- id выводится из содержимого. Одно и то же фото не попадает в проект дважды, а пропавший оригинал находится повторным импортом или поиском по хэшу.
- Статус ассета (есть ли прокси, на месте ли оригинал) в project.json не пишется: при открытии он вычисляется заново.

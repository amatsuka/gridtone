# 0026. План контента и экспорт плана

**Статус:** принято, 2026-10-14. Уточняет ADR 0017, 0022 и 0023. Корзины подсказки — стартовые, их калибрует ручной чек-лист этапа 5; кандидаты из библиотеки в карточке — этап 6.

**Контекст.** Спека (модуль 4, «Режим «План контента»»): пустые позиции получают карточки — номер в порядке публикации, образец целевой яркости и цвета, словесная подсказка («светлый, холодный, мало насыщенный») и кандидаты из библиотеки; подсказка собирается из корзин L, температуры и хромы; план экспортируется в Markdown или CSV и картинкой целевой сетки. Открытыми были вопросы:
- каким позициям нужна карточка и откуда в ней номер и цель;
- границы корзин и что писать у цели без цвета;
- как карточки показывают паттерн «пачками по 3» и неполную пачку;
- колонки и форматирование `План.md` и `План.csv`, кодировка и разделитель;
- раскладка и цвета `Цели.png`, кто считает тексты и пиксели;
- что делать с кандидатами, пока библиотеки нет.

**Решение.** `src/core/pattern/plan.ts` — карточки (`contentPlan`), подсказка (`targetHint`), образец (`targetSwatch`), тексты (`planMarkdown`, `planCsv`); `src/core/pattern/targetGrid.ts` — пиксели `Цели.png`. В renderer — раздел «План контента» вкладки «Цель» (`ContentPlanSection.tsx`) и раздел «План» диалога экспорта; в main — раздел `plan` в `export:run` (`planExportItem`); utility process пишет файлы. План — производные данные: в проект и историю не пишется.

1. **Карточки** — на каждую позицию плана публикации (`planOrder`, ADR 0022), по порядку публикации: запланированные посты, пустые позиции и закреплённые последними. Это шире спеки («пустые позиции»): у запланированного поста место в плане и цель те же, а план для публикации нужен целиком.
   - Номер — номер в плане; он же на плитке («6-й») и в имени файла поста (ADR 0022, п. 7).
   - Цель — `slot.target` как есть: проекция паттерна, после «Переставить» со сдвигом фазы — сдвинутые клетки (ADR 0025). Из паттерна план её не пересчитывает. У закреплённой цели нет, даже вписанной в файл проекта (ADR 0022, п. 5).
   - Фото — имя файла оригинала; у пустой позиции — «пусто — сюда нужен пост».
   - «Ниже опубликованного» — как на плитке, красным, с той же оговоркой (`belowPublishedNote`).
   - Место под кандидатов — строка «кандидаты появятся с библиотекой»: подбор — этап 6.
   - Клик по карточке выделяет позицию, ⌘ и Shift — как в карте яркости.
2. **Подсказка** (`targetHint`) — «L-слово, температура, хрома»:

   | Часть | Корзины | Откуда |
   | --- | --- | --- |
   | L | тёмный < 0.53 ≤ средний < 0.71 ≤ светлый | середины между уровнями по умолчанию 0.44, 0.62, 0.80 |
   | температура | холодный < −0.01 ≤ нейтральный ≤ 0.01 < тёплый | допуск температуры выбросов (ADR 0020) |
   | хрома | мало насыщенный < 0.04 ≤ умеренно насыщенный < 0.1 ≤ насыщенный | |

   - Температура цели — та же величина, что у плиток (`temperature`, ADR 0018): координата (a, b) цели вдоль оси температуры в базисе «температура, оттенок». Сильный оттенок к пурпурному не делает цель «холодной».
   - У цели без цвета (строка, серая ячейка картинки, полосы без цвета уровней) — «светлый, цвет любой».
   - Без тона, но с хромой — «тон любой» вместо температуры (середина градиента «теплее»); тон без хромы (только ручной project.json) — температура по направлению тона и «насыщенность любая».
   - Без цели — «цели нет».
3. **Образец** (`targetSwatch`) — OKLab цели (`targetLab`) в sRGB 8 бит со срезом в охват (`labToSrgb8`), без цвета — серый той же L. Им же залиты плитки `Цели.png`, а `targetCss` образцов вкладки «Цель» даёт тот же цвет.
4. **Пачки.** У паттерна «пачками» карточки ленты группируются по три по номерам: пачка k — номера 3k − 2…3k. Закреплённые — отдельной группой «Закрепить»: они вне ленты и ленту не сдвигают. Если позиций ленты в плане не кратно трём — предупреждение «последняя пачка неполная, лента сдвинется на неполный ряд» (ADR 0023, п. 8). У одиночных постов групп нет.
5. **Предупреждения плана** — во вкладке, в диалоге экспорта и в `План.md`: пост ниже опубликованного; неполная пачка; «У позиций плана нет целей: примените паттерн к сетке», если целей нет ни у одной карточки.
6. **`План.md`** — заголовок «# План контента — <проект>», строка паттерна (источник, период, режим публикации) или «Паттерна нет.», порядок, «**Внимание:**» со списком предупреждений и таблица: №, Пачка (только у «пачками»), Позиция («4 · ряд 2, колонка 1»), Фото, Цель («L 0.62, тон 250°, хрома 0.060», «, мягкая»), Цвет («#RRGGBB»), Подсказка, Заметка («закрепить», «ниже опубликованного»). Ячейки: переводы строк — пробелом; «\», «`», «*», «_», «[», «]», «<», «>», «|» и «#» — с обратной косой чертой. Строки — LF. Без позиций — без таблицы.
7. **`План.csv`** — RFC 4180: запятая, строки CRLF, поле с кавычкой, запятой или переводом строки — в кавычках, кавычка удваивается; UTF-8 с BOM — иначе Excel откроет кириллицу не в той кодировке; точка в числах. Колонки: Номер, Пачка, Позиция, Ряд, Колонка, Фото, Закрепить («да»), L (3 знака), Тон (целые градусы, 359.6° — 0), Хрома (3 знака), Цель («жёсткая», «мягкая»), Цвет, Подсказка, Заметка. Колонки одни и те же при любом паттерне; пустое поле — величины нет.
8. **`Цели.png`** — раскладка `Сетка.png` (`gridLayout`, ADR 0017, п. 5): все позиции по порядку сетки, опубликованные тоже; плитка 540 px залита образцом цели позиции; без цели и закреплённая — `GRID_EMPTY`, промежутки — `GRID_BACKGROUND`. RGB 8 бит, sRGB вшит. Номеров на картинке нет: текст рисовать нечем, а номера — в `План.md`.
9. **Где идёт работа.**
   - Запрос: `plan: { markdown, csv, image }` в `ExportRequest` — три флага; main проверяет форму.
   - main (`planExportItem`): тексты считает core по проекту main; для картинки — только цвета позиций (`targetGridColors`), не 100 МБ пикселей через IPC. Бросает до диалога папки: формат не выбран; в плане нет позиций (для текстов); в сетке нет плиток или у позиций нет целей (для картинки).
   - utility process: `План.md`, `План.csv` — готовый текст; `Цели.png` — пиксели `targetGridImage` из core и sharp. Всё — в ту же новую подпапку экспорта с флагом `wx`, после сетки.
   - Имена `План` и `Цели` занимаются вместе с картой и сеткой, раньше образов: образ «План» станет «План 2».
   - В диалоге — раздел «План», по умолчанию не отмечен: прежние экспорты не меняются. Тексты недоступны без позиций в плане, картинка — без целей.

**Отвергнуто.**
- **Карточки только у пустых позиций**, как в спеке. План публикации — все позиции плана: и пост с фото публикуется под своим номером, и в CSV нужен весь порядок.
- **Цель карточки из паттерна** (`targetAt`). После ручной правки project.json или в проекте без паттерна план показал бы не то, что сверяют режим 7 и подгонка.
- **Температура по b** (тёплый — b > 0). Расходилась бы с температурой плиток и поправок, а оттенок к пурпурному давал бы «холодный».
- **Точка с запятой** — разделитель Excel с русской локалью. План требует RFC 4180; Numbers и Google Таблицы читают запятую, Excel — через «Данные → Из текста». Проверка — ручной чек-лист.
- **Пиксели `Цели.png` в main** и передача в utility process: на 90 позициях это 100 МБ через IPC.
- **Номера на `Цели.png`.** Рисовать текст в core нечем, а SVG-текст sharp зависит от шрифтов системы.
- **Пачки по рядам сетки**, а не по номерам. При неполном плане пачка, выровненная по ряду, всё равно сдвинет ленту на неполный ряд; честнее предупредить.

**Последствия.**
- План пересчитывается на каждый снимок проекта — миллисекунды на 90 позициях, воркер не нужен.
- Подбор этапа 6 положит кандидатов в карточку на место строки «кандидаты появятся с библиотекой».
- Числа корзин — в core (`plan.ts`) и меняются без нового ADR, если смысл сохраняется.

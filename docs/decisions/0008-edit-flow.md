# 0008. Поток правок: патчи из renderer

**Статус:** принято, 2026-10-07. Пункт «Что можно менять» заменён проверкой по инвариантам — [ADR 0010](0010-patch-invariants.md).

**Контекст.** Ползунок шлёт десятки изменений в секунду, и плитка должна откликаться в том же кадре. Проектом владеет main (ADR 0005): только он пишет project.json, а на этапе 0 каждое изменение уходило в renderer полным снимком. Гонять полный проект через IPC на каждое движение ползунка, туда и обратно, расточительно. К тому же renderer ждал бы ответа main, прежде чем перерисовать плитку.

**Решение.**
- **Renderer правит у себя.** Он меняет свою копию проекта через Immer (`produceWithPatches`), сразу перерисовывает плитку и отправляет патчи пакетом по каналу `project:patch`: `{ dir, seq, patches }`.
- **Main применяет пакет** через `ProjectSession.update`, поэтому автосохранение работает как прежде. Полный снимок обратно не уходит, только событие `project:status` с состоянием сохранения.
- **Что можно менять.** `applyProjectPatches` в core принимает только пути `slots[i].adjust…` и `slots[i].crop…`. Пакет атомарен: если хоть один патч запрещён или выводит коррекцию либо кадр за пределы (`isValidAdjust`, `isValidCrop`), не применяется ничего. Ключи `__proto__`, `constructor` и `prototype` запрещены. Пути к оригиналам, состав сетки и статусы из renderer не меняются.
- **Изменения из main** (импорт, пересборка прокси) по-прежнему приходят полным снимком. В снимке есть `patchSeq` — номер последнего применённого пакета. Renderer берёт снимок за основу и заново накладывает свои пакеты с большим номером: те, что ещё в пути. Поэтому снимок, пришедший посреди движения ползунка, правку не откатывает.
- **`dir` в пакете.** Пакет, отправленный до смены проекта, не применится к другому проекту.
- **Ошибка.** Если main отверг пакет, renderer запрашивает `project:get` и заменяет свою копию.

**Отвергнуто.**
- **Полный проект через IPC на каждое изменение.** Сотни килобайт на событие ползунка в обе стороны.
- **Отдельные каналы на каждое действие** (`adjust:set` и т. п.). Каждое новое действие потребовало бы нового канала. Патчи Immer покрывают все правки этапа 2 (кривые, HSL, кадр, копирование правок), а для undo/redo Immer сам даёт обратные патчи.
- **Хранить проект только в renderer.** Main не смог бы сохранять проект при выходе, и сломалась бы модель ADR 0005.

**Последствия.**
- **Undo/redo (этап 2)** строится на обратных патчах в renderer. В main уходят те же пакеты.
- **Новые поля, которые renderer правит**, добавляются в разрешённые пути `applyProjectPatches` и в проверку `validate.ts`.
- **Порядок слотов** — массив, и патчи адресуют слот по индексу. Когда появится перетаскивание (этап 2), сами перестановки пойдут тем же каналом. Main должен будет применять их в том же порядке.

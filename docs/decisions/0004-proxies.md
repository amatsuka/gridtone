# 0004. Прокси: размеры, формат, цвет

**Статус:** принято, 2026-10-06.

**Размеры.** В спеке сказано «2048 и 512 px», но не уточнено, по какой стороне.
- **2048 — по длинной стороне.** Редактор видит весь кадр.
- **512 — по короткой.** Плитка показывает окно 3:4 внутри кадра. Если бы 512 было по длинной стороне, у горизонтального снимка окно получилось бы 256 px в ширину, и на ретине плитка была бы мыльной.
- Фото меньше этих размеров не увеличиваются.

**Формат.**
- JPEG q92 с цветностью 4:4:4 без прореживания: прореживание цветности на прокси исказило бы цвет, а цвет — главное в приложении.
- Внутрь вшит sRGB-профиль.
- Путь: `cache/proxies/<assetId>/{512,2048}.jpg`.
- Запись атомарная: временный файл, затем rename. Поэтому под итоговым именем всегда лежит целый файл, а наличие файла означает, что прокси готов.

**Цвет.** Порядок операций sharp:

```
autoOrient → pipelineColourspace('srgb') → resize → flatten(#fff) → withIccProfile('srgb') → jpeg
```

Проверено на JPEG, PNG 8/16 бит, WebP, TIFF, CMYK и ч/б, с профилем P3 и без профиля:
- **Без `pipelineColourspace('srgb')`** 16-битные файлы получают неверный цвет: 200/100/30 превращается в 216/93/0 для файла без профиля и в 187/105/49 для P3. Ошибка молчаливая.
- **Без `withIccProfile('srgb')`** 8-битные файлы sharp переводит в sRGB, но профиль не вшивает.

Обе ошибки ловят тесты в tests/indexer/proxies.test.ts. При мутации конвейера они падают.

**id ассета** — первые 16 hex-символов SHA-256 файла. Благодаря этому одно и то же фото кэшируется один раз, а протокол может отдавать прокси с `Cache-Control: immutable`. Если рецепт прокси когда-нибудь изменится, версию рецепта нужно добавить в путь кэша.
